# Hugo → Astro Migration Plan (Full Overhaul)

**Branch:** `feat/astro-migration`
**Goal:** Rebuild `marcelaviola.com` on Astro with modern best practices and performance/SEO/accessibility optimizations, **without changing the deployment or distribution strategy**.

---

## 0. Guiding Principles

1. **Deployment strategy is frozen.** Hosting stays on **Cloudflare Pages with Git integration (auto-build on push)**. The repo, the branch-based trigger, the custom domain, DNS, and the CDN all stay exactly as they are.
2. **Zero functional regressions.** The rebuilt site must be visually and behaviorally identical (or better) before we merge.
3. **Ship less to the browser.** Astro's zero-JS-by-default model replaces the current hand-rolled JS. Every kilobyte of JS must justify itself.
4. **Delete technical debt, don't port it.** Grunt, Bower, the UA-sniffing scripts, and the custom lazy-loader are removed, not translated.
5. **Content stays editable by a non-developer.** Copy and data live in clearly-named, well-typed files.

---

## 1. Deployment & Distribution — What Stays, What Changes

### Stays identical (the "strategy")
- **Host:** Cloudflare Pages, Git-integration model (auto-build on push to the connected branch).
- **Trigger:** `git push` to the production branch → Cloudflare builds and deploys automatically. Preview deploys on other branches keep working.
- **Domain:** `www.marcelaviola.com` via the existing `CNAME`. No DNS changes.
- **Repo & remotes:** unchanged (`github.com:natos/marcelaviola.com`).
- **`gh-pages` branch:** left untouched (can be retired later, out of scope).

### Changes (two dashboard settings only — not the strategy)
| Setting | Now (Hugo) | After (Astro) |
|---|---|---|
| Build command | `hugo` (implicit/preset) | `npm run build` |
| Build output directory | `public` | `dist` |
| Framework preset | Hugo | Astro |
| Node version | n/a | pinned via `.nvmrc` / `NODE_VERSION` env |

> **Why the output dir moves to `dist`:** In Astro, `public/` is the *input* folder for unprocessed static assets, and `dist/` is the *build output*. Fighting that convention causes more problems than it solves. Cloudflare's output-dir field is a one-time change in the dashboard.

### Deployment-preservation checklist
- [ ] `CNAME` file present in Astro's `public/` so it lands in `dist/` on build.
- [ ] `robots.txt`, `humans.txt`, `sitemap.xml`, `service-worker.js`, `llms.txt` all emitted to `dist/` root.
- [ ] Pin Node with `.nvmrc` and/or the `NODE_VERSION` Pages env var to avoid surprise build breaks.
- [ ] First deploy validated on a Cloudflare **preview** URL before touching the production branch.
- [ ] Update the two dashboard settings in the **same window** as the production merge to avoid a broken production build.

## 4. Data Migration (TOML → typed TS)

- Convert each `data/*.toml` into a typed module under `src/data/`. Prefer `.ts` with exported typed objects so the editor autocompletes and the build fails on typos.
- Centralize all site metadata (`title`, `description`, `keywords`, `baseurl`, nav items, author, photographer credits) into `src/data/site.ts` — this replaces `config.toml [params]` and the `[[menu.main]]` entries.
- Testimonials currently live as hard-coded HTML in `testimonials.html`; extract them into `src/data/testimonials.ts` (name, quote, optional photo) and render by mapping. This makes them editable and enables schema.org `Review` markup.

**Best practice:** validate data shapes with a small Zod schema (or Content Collections) so malformed data breaks the build instead of the live site.

---

## 5. Template & Component Migration

### Partials → Astro components
Each partial becomes a `.astro` component. Hugo's `{{ range }}`/`{{ .Var }}` becomes JS `.map()` and `{expr}` in the component template. Props replace Hugo's context (`.`).

### Shortcodes → components or MDX
- Presentational shortcodes (`hero`, `images`, `gallery`, `image`, `icon`, `youtube`, `slider`) → reusable Astro components.
- If the Markdown pages (`classes`, `shows`, `workshops`) rely on shortcodes inline, enable **MDX** so those pages can import and use the same components directly. This is the cleanest 1:1 replacement for Hugo shortcodes-in-markdown.
- `smooth-link` / `target-blank` shortcodes disappear — replaced by plain anchors plus global CSS `scroll-behavior` (already present) and a small link-hardening step (`rel="noopener noreferrer"` on external links).

### Layouts
- `index.html` → `BaseLayout.astro` + `pages/index.astro` composing the section components in the same order (hero → about → credentials → services → testimonials → contact → footer).
- `_default/single.html` → `pages/[...slug].astro` or a `PageLayout.astro` used by content collections.
- `404.html` → `pages/404.astro` (Cloudflare Pages serves `404.html` automatically).

---

## 6. Content Collections (type-safe content)

- Define `src/content/config.ts` with collections for `pages` (marketing subpages) and optionally `blog`.
- Benefits over raw Hugo content: schema validation, typed frontmatter, autocompleted queries, and build-time errors for missing fields.
- Decide per page whether it stays Markdown/MDX (editable prose) or becomes a hand-built `.astro` (layout-heavy). `classes`/`shows`/`workshops` are prose-heavy → MDX. The home page is layout-heavy → `.astro`.

## 7. Asset Pipeline — Replacing Grunt + Bower Entirely

| Old (Grunt/Bower) | New (Astro/Vite) |
|---|---|
| `grunt responsive_images` (x1/x2 variants) | `astro:assets` `<Image>`/`<Picture>` — automatic responsive `srcset`, widths, and modern formats |
| `grunt imagemin` | `astro:assets` (Sharp) compresses at build time |
| `grunt uglify` (JS bundling) | Vite (built into Astro) bundles/minifies only shipped JS |
| `bower` deps (`smooth-scroll`, `instagramas`) | Removed — smooth scroll is native CSS; Instagram feed re-evaluated (static data or an island) |
| `grunt watch` | `astro dev` HMR |
| CDN Font Awesome (~77 KB CSS) | Inline **only the handful of icons used** via `astro-icon` (removes the entire CDN dependency + render-blocking request) |

**Images:** move source images into `src/images/` so `astro:assets` can process them. Files that must keep exact paths/URLs (videos, anything referenced by the service worker) stay in `public/`.

## 8. Performance Optimizations (the overhaul wins)

1. **Ship ~0 KB JS by default.** Only the nav toggler and any genuinely-interactive widget become tiny scripts or client islands. The custom `images.js` hi-res swapper is deleted — replaced by native `<img loading="lazy">` + `astro:assets` `srcset`, which the browser handles better.
2. **Modern image formats + responsive srcset** via `<Picture>`: AVIF/WebP with JPEG fallback, correctly-sized variants per breakpoint. Replaces the manual `x1`/`x2` + `data-lowres`/`data-highres` scheme.
3. **Kill render-blocking Font Awesome.** Inline just the ~3 social icons used (Instagram, YouTube, LinkedIn) as SVG. Removes a full CDN round-trip and 77 KB.
4. **Self-host & subset fonts** (Bebas Neue, Work Sans) with `font-display: swap` and `preload` for the primary weight; drop the Google Fonts round-trips. Optionally use Fontsource.
5. **Replace UA sniffing for the hero video** with CSS media queries (`.desktop`/`.mobile` already exist) + `<video>` `preload="metadata"`, `poster` for instant first paint, and correct `autoplay muted playsinline loop`. Removes the giant regex inline script.
6. **Lazy-load below-the-fold media**; eager-load only the hero.
7. **Critical CSS inlined** by Astro; defer the rest.
8. **View Transitions** (Astro's `<ClientRouter>`) for smooth section/page transitions — respecting `prefers-reduced-motion` (already handled in CSS).
9. **Cache-busting via hashed asset filenames** (Vite default) — better long-term caching on Cloudflare's CDN.
10. **Preload the hero video/poster** and preconnect only to origins actually used.

**Target:** Lighthouse 95+ across Performance/SEO/Best-Practices/Accessibility; near-zero shipped JS.

---

## 9. SEO Improvements

1. **HTTPS everywhere.** Replace remaining `http://` in config/`robots.txt`/`sitemap` with `https://www.marcelaviola.com`.
2. **Structured data (JSON-LD):** `Person`/`LocalBusiness` for Marcela, `Review`/`AggregateRating` from testimonials, `BreadcrumbList` where relevant.
3. **Complete Open Graph & Twitter cards:** add `og:locale`, correct absolute image URLs, per-page titles/descriptions (currently a couple of OG tags reference the wrong-cased `.Description`).
4. **Auto-generated sitemap** via `@astrojs/sitemap`, and a correct `robots.txt` pointing at the HTTPS sitemap.
5. **Canonical URLs** generated per page.
6. **Per-page meta** (title/description) instead of one global description.
7. **Semantic headings & landmarks** audited (single `<h1>` per page, logical order).
8. **`llms.txt`** at the site root — a curated, markdown summary of the site (name, mission, key pages, contact) following the [llmstxt.org](https://llmstxt.org) spec, so LLMs and AI crawlers get accurate, structured context. Lives in `public/llms.txt` → emitted to `dist/` root. Keep it in sync with `src/data/site.ts` (single source of truth) so it never drifts; optionally generate it at build time from that data.

## 10. Accessibility Improvements

1. **Real `alt` text** on every image (currently all `alt=""`).
2. **Skip-to-content link** for keyboard users.
3. **Accessible nav toggler:** `aria-expanded`, `aria-controls`, focus management, ESC to close, focus-visible styles.
4. **External links** get `rel="noopener noreferrer"` and, where useful, screen-reader hints for "opens in new tab".
5. **Respect `prefers-reduced-motion`** in JS-driven motion (video/transitions), not just CSS.
6. **Color-contrast pass** on the pink-on-black link colors.
7. **Form/CTA labels** verified (contact CTAs point to Zoho/email — ensure descriptive link text).

## 11. PWA / Service Worker

- Replace the hand-written `service-worker.js` + `register.js` with **`@vite-pwa/astro`** (Workbox under the hood): precache, runtime caching strategy, auto-versioning (no more manual `const version = '2'`), and offline fallback.
- Add a **`manifest.webmanifest`** (name, icons, `theme_color`, `background_color`, `display`) for installability — currently missing.
- Ensure the generated SW and manifest land at `dist/` root so scope `/` is preserved (same behavior as today).

## 14. Phased Execution Plan

Each phase is independently reviewable; the site keeps building on Cloudflare previews throughout. Production dashboard settings change only at the very end.

**Phase 0 — Scaffolding (no user-visible change)**
- `npm create astro` (minimal), add `@astrojs/sitemap`, `@astrojs/mdx`, `astro-icon`, `@vite-pwa/astro`.
- Add `.nvmrc`, tsconfig, lint/format configs, base `package.json` scripts.
- Move deploy-critical files into `public/` (`CNAME`, `robots.txt`, `humans.txt`).

**Phase 1 — Foundation**
- `BaseLayout.astro`, `Head/SEO.astro`, port `global.css`.
- Migrate `config.toml`/data TOML → `src/data/*.ts` (+ Zod/collection schemas).
- Self-host fonts; inline used icons.

**Phase 2 — Home page parity**
- Build section components (`HeroVideo`, `About`, `Credentials`, `Services`, `Testimonials`, `Contact`, `Footer`, `Menu`, `Social`, `Toggler`) and compose `index.astro`.
- Replace image markup with `astro:assets` `<Picture>`; real `alt` text.
- Replace UA-sniff video logic with CSS + `poster`.

**Phase 3 — Subpages & content**
- MDX for `classes`/`shows`/`workshops`; port shortcodes → components.
- Blog post handling (keep or drop `angular-switchery`).
- `404.astro`.

**Phase 4 — PWA, SEO, A11y hardening**
- `@vite-pwa/astro` + `manifest.webmanifest`.
- JSON-LD, sitemap, canonicals, OG/Twitter completion.
- Accessibility pass (skip link, aria, contrast, alt audit).

**Phase 5 — QA & parity sign-off**
- Visual diff vs. current site, link check, Lighthouse, cross-device video autoplay test (iOS Safari especially).
- Verify `dist/` contains `CNAME`, SW, manifest, sitemap, robots.

**Phase 6 — Cutover (deployment preserved)**
- Merge to production branch **and** flip the two Cloudflare settings (build command → `npm run build`, output dir → `dist`, preset → Astro) together.
- Watch the first production build; validate live domain + SW scope.
- Retire Grunt/Bower files. `gh-pages` branch left as-is (optional cleanup later).

- [ ] Visual parity (or approved improvements) on the one-page site and all subpages.

- [ ] Hero video autoplays on desktop **and** iOS Safari (the historically fragile case).
- [ ] `dist/` root contains `CNAME`, `robots.txt`, `humans.txt`, `llms.txt`, `sitemap.xml`, service worker, `manifest.webmanifest`.
- [ ] Lighthouse ≥ 95 Performance/SEO/Best-Practices/Accessibility on mobile.
- [ ] Shipped JS is minimal (ideally only the nav toggler island).
- [ ] Cloudflare **preview** deploy is green before production settings change.
- [ ] No `http://` references remain.

## 16. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Cloudflare production build breaks at cutover | Validate on preview URL first; change dashboard settings only at merge; pin Node via `.nvmrc`. |
| iOS video autoplay regressions | Keep `muted playsinline autoplay loop` + `poster`; test on real iOS before cutover. |
| Deploy-critical files missing from `dist/` | Keep them in `public/`; add a QA checklist item verifying `dist/` contents. |
| SEO dip from URL/markup changes | Preserve URLs, add canonicals + sitemap, keep redirects if any path changes. |
| Service-worker cache serving stale build | `@vite-pwa/astro` auto-versioning + skipWaiting/clientsClaim strategy. |
| Icon/font parity drift | Snapshot-compare rendered pages before/after. |
